# 技术文档 · chinese-report-voice

**定位** 中文正式文档的文风与版式门禁（独立技能）｜**运行时** Python 3.9+；`.docx` 需 python-docx，`.pdf` 需 pymupdf，纯文本零依赖

## 1. 定位

不是写作助手，是**交付前的检查器**。它把"像不像给评委看的"拆成可判定的项：文体归属、语体特征、版式硬伤。判断权仍在人——脚本只报不改。

## 2. 输入契约

| 输入 | 支持 | 说明 |
|---|---|---|
| 纯文本 | `.txt` / `.md` | 零依赖 |
| Word | `.docx` | 需 python-docx |
| PDF | `.pdf` | 需 pymupdf |
| 代码 | `.py` | 只抽字符串字面量，跳过代码与注释 |

## 3. 输出契约

- 违规清单：按类型分组（口语词 / 破折号 / 自我削弱句 / 套话），附位置
- 退出码：`0` 通过 ｜ `1` 硬性违规（必须改）｜ `2` 仅提示项（可判断后放行）
- 排版体检四项结果：纸张、薄页、表格越界、目录页码

## 4. 判定逻辑

### check_voice.py

1. 抽取正文（按扩展名分流；代码只取字符串字面量）
2. 扫查硬性项：破折号 `——`、口语词、自我削弱句
3. 扫查提示项：书面套话、可疑表述
4. 有硬性项 → 1；仅有提示项 → 2；否则 → 0

**只报不改**：改哪句必须人判断，脚本只负责把问题摊在眼前。

### check_pdf_layout.py

| 检查 | 判据 |
|---|---|
| 纸张 | 是否 A4（595×842 pt）；Letter 是 612×792，一眼可辨 |
| 薄页 / 空白页 | 正文字数低于阈值（默认 330，可用 `--min-chars` 调）的页全部列出 |
| 表格越界 | 表格外框超出「页宽 − 边距」即报；边距用 `--margin` 指定 |
| 目录页码 | 逐条比对目录声明页与章节标题实际所在页 |

### 已知限制

| 限制 | 后果 | 缓解 |
|---|---|---|
| 关键词式判定，不懂语义 | 正当地使用某个词也会被报 | 退出码 2 的提示项允许人判断放行 |
| 不同文体共用一套词表 | 技术文档里的口语词可能合理 | 按文体选择是否采信提示项 |
| 表格越界基于外框 | 单元格内文字溢出不一定报 | 出 PDF 后人工翻一遍表格页 |
| 目录比对依赖标题识别 | 标题格式不规范时可能误报 | 目录项与标题保持同名同层级 |

## 5. 能力边界

**能做**：判文体、查语体特征、查四类版式硬伤、给出可复核的违规清单。

**不能做**：改写文风（只报不改）、核实事实真伪、替代模板要求、判断内容价值。

## 6. 设计取舍

| 选择 | 为什么不选另一条路 |
|---|---|
| 只报不改 | 自动改写会掩盖作者判断，且改错难追溯 |
| 退出码分 1/2 两档 | 硬性项与提示项混在一起会逼人全部忽略 |
| 排版单独一个脚本 | 文风与版式是两类问题，混在一个报告里无法分派处理 |
| 支持 docx/pdf | 交付物是这两种格式，只查 md 等于没查最终形态 |

## 7. 优缺点

**优点**：把"像不像正式文档"变成可跑的命令；硬性问题零容忍、软性问题留判断空间；排版四项都是被退回过的真实类型。

**缺点与缓解**

| 缺点 | 影响 | 缓解 |
|---|---|---|
| 词表判定不理解语境 | 误报 | 提示项人工放行，不当硬性 |
| 依赖第三方库读 docx/pdf | 环境缺则跑不了 | 先导出纯文本再查，或装对应库 |
| 不能判断论证质量 | 通顺但无逻辑仍能过 | 靠人过发现链、数据出处 |

## 8. 失败模式与处置

| 现象 | 根因 | 处置 |
|---|---|---|
| 退 1 但指出的是引文原文 | 引用了含口语词的原文 | 引文用引号框定后豁免，或改写转述 |
| 退 1 报自我削弱句 | 结论句写得过谦 | 删掉整句，改为正面判断 |
| 排版体检全过但成品仍难看 | 检查项覆盖面有限 | 人工翻一遍薄页与表格页 |
| docx 读取失败 | 未装 python-docx | 装库，或先另存为 txt |

## 9. 与其他技能的关系

**无依赖**。可与任何写作流程搭配，通常放在交付前最后一步执行。
